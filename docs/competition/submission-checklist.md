# Submission Checklist

## Repository

- [x] Public GitHub repository.
- [x] MIT License.
- [x] Architecture and startup documentation.
- [x] Environment template and dependency files.
- [x] Data source and license notes.
- [x] v1 tag `v1.0.0`.
- [x] v2 branch and incremental commit history.
- [x] GitHub Actions for API contract tests and frontend build.
- [ ] Final `v2.0.0` tag.

## Team Information

- [ ] School.
- [ ] Group.
- [ ] Member names and student IDs as required.
- [ ] Roles and contributions.
- [ ] Advisor information.

## Materials

- [ ] 5-8 minute MP4 demonstration, at least 1080p.
- [ ] Mandarin narration.
- [ ] Technical report PDF, no more than 30 pages.
- [ ] Innovation-point summary checked against implementation evidence.
- [ ] Screenshots or video frames for README.

## Deployment

- [ ] Public demo URL.
- [ ] Review-period availability.
- [ ] API key injected through environment variables.
- [ ] Neo4j service started before review.
- [ ] Health check verified from the public network.

## Final Freeze

- [ ] Run full Python tests.
- [ ] Run frontend lint and production build.
- [ ] Verify GitHub Actions on the final commit.
- [ ] Verify no secrets, model weights, caches, or OCR language data are tracked.
- [ ] Merge v2 into the release branch.
- [ ] Create final tag and GitHub Release.
- [ ] Submit repository URL and all required materials through the official
      competition portal.
